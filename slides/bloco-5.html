create-vue, Vue e Vite: três responsabilidades

create-vue · gerador

Pergunta opções e escreve os arquivos iniciais. Roda uma vez, na criação.

Vue · framework

Biblioteca usada pelo seu código: componentes, template, reatividade. Vai para o navegador.

Vite · ferramenta

Serve os fontes no desenvolvimento e gera o build. Roda no Node, no seu computador.

Por que este caminho?

npm create vue@latest é o fluxo indicado pelo guia oficial e gera um projeto baseado em Vite. Nada é instalado globalmente: o npm baixa o gerador sob demanda.

Alternativas e limites

Vue funciona sem Vite em outros cenários (script direto na página, sem build). npm create vite@latest também cria projetos Vue. O Vue CLI está em manutenção: não é o caminho para projetos novos.

PerguntaVue exige Vite em qualquer cenário? Qual das três peças aparece em dependencies?

Fundamento

Gerador (create-vue) cria a estrutura; framework (Vue) define como escrever componentes e reage a mudanças de estado; ferramenta de desenvolvimento (Vite) transforma arquivos .vue e módulos para o navegador, com servidor de desenvolvimento e build de produção. Confundir as três é a origem de perguntas como “instalo o Vite ou o Vue?”.

Distinção

Usar Vite aqui é alternativa escolhida para o percurso, não condição universal. Instalar o gerador globalmente é possível, mas cria diferenças entre máquinas e versões; npm create evita isso.

Resposta esperada

No package.json gerado, só vue está em dependencies; vite está em devDependencies; create-vue não aparece.

dev, build, preview e publicação não são a mesma coisa

EtapaComandoO que aconteceQuem vê
Desenvolvimentonpm run devServe os fontes, transforma sob demanda, atualiza ao salvarVocê, em localhost
Buildnpm run buildGera artefatos otimizados em dist/ e terminaNinguém ainda
Previewnpm run previewServe dist/ localmente para conferir o buildVocê, em localhost:4173
Publicação(hospedagem)Envia dist/ para um servidor acessívelQualquer pessoa

PerguntaPor que npm run dev não equivale a publicar? O que preview verifica?

Fundamento

Servir fontes durante o desenvolvimento, gerar artefatos e conferir o build são etapas distintas. O build junta e reduz os módulos, gera nomes com hash para cache e copia public/. preview confere o resultado do build localmente; não é servidor de produção nem publicação. Publicar exige uma hospedagem de arquivos estáticos (fora do escopo do módulo).

Convenção × regra

Os nomes dev, build e preview são convenção do gerador; o que importa é o comando associado em scripts.

Desafio em dupla: pasta, script ou porta?

Para cada caso: hipótese → evidência que a distingue → uma mudança → resultado.

Só depois da hipótese registrada

Executei [comando] na pasta [pasta atual] e recebi [primeiras linhas do erro]. Nossa hipótese é [hipótese]. Dê uma única pista ou pergunta de diagnóstico, sem a solução, e diga qual evidência confirmaria ou refutaria a hipótese.

Dica

Leia a primeira linha de erro: o problema é encontrar um arquivo, encontrar um nome ou ocupar um recurso?

Mostrar solução (após a tentativa)

A: pasta errada — não há package.json ali (pré-requisito ausente); entre na pasta do projeto. B: serve é o nome do Vue CLI; aqui é dev (convenção; npm run lista os válidos). C: dois processos no mesmo endereço e porta (impossível naquele momento); encerre o outro ou escolha outra porta (alternativa válida).

Condução

Cada dupla escolhe um caso, registra a hipótese e só então pode usar o prompt. Reproduza ao vivo pelo menos um: cd .. e npm run dev (caso A). O caso B liga-se à questão teórica 5, cujo manifesto usava vue-cli-service serve.

Contraste importante

“Port 5173 is in use, trying another one...” (slide 52) não é erro: o Vite escolheu outra porta e seguiu. No caso C o servidor não tem essa estratégia e termina. Com --strictPort, o Vite também falharia em vez de trocar de porta.

Quatro situações

Impossibilidade naquele ambiente · pré-requisito ausente · alternativa válida com outra configuração · convenção escolhida. Evita ensinar preferências como regras universais.
